# Электроника с нуля — обучающий сайт для начинающих

Одностраничный образовательный сайт про электронику и embedded-платформы (Arduino, ESP32/ESP8266,
STM32, Raspberry Pi, NVIDIA Jetson, BeagleBone, Orange Pi) для новичков. Проект разделён на
`frontend` (статический сайт на HTML/CSS/JS) и `backend` (Node.js + Express API).

## Структура проекта

```
lab/
├── backend/          # Express-сервер + API подписки
│   ├── server.js
│   ├── routes/
│   ├── controllers/
│   ├── services/
│   ├── middleware/
│   └── data/subscribers.json
└── frontend/          # Статический сайт
    ├── index.html
    ├── css/
    └── js/
```

## Требования

- [Node.js](https://nodejs.org/) версии 18 или новее (включает npm).

## Установка и запуск

```bash
cd backend
npm install
npm run dev      # либо npm start — запуск без автоперезапуска
```

Сервер поднимется на `http://localhost:3000` и одновременно отдаёт:
- статический фронтенд из `frontend/` (открыть `http://localhost:3000` в браузере);
- API по префиксу `/api`.

Порт можно изменить переменной окружения `PORT`, например: `PORT=4000 npm start`.

### Альтернативный запуск фронтенда отдельно

Если хочется открыть `frontend/index.html` напрямую (двойным кликом) или через расширение
Live Server в другом порту — это тоже сработает: на бэкенде уже подключён `cors()`, поэтому
запросы с `subscribeForm.js` на `http://localhost:3000/api/subscribe` пройдут без CORS-ошибок.
Backend в этом случае всё равно должен быть запущен отдельно (`npm run dev` в `backend/`).

## API

| Метод | Путь              | Описание                                                        |
|-------|-------------------|-------------------------------------------------------------------|
| POST  | `/api/subscribe`  | Добавить подписчика. Тело: `{ name, email, interest? }`.         |
| GET   | `/api/subscribers`| Список всех подписчиков (демонстрационный эндпоинт для проверки).|

Проверка через curl:

```bash
curl -s http://localhost:3000/api/subscribers
curl -s -X POST http://localhost:3000/api/subscribe \
  -H "Content-Type: application/json" \
  -d '{"name":"Аня","email":"anya@example.com","interest":"esp32"}'
```

Данные сохраняются в `backend/data/subscribers.json`.

## Просмотр данных (админка)

Служебная страница `http://localhost:3000/admin` показывает таблицу всех подписчиков
(`frontend/admin.html` + `frontend/js/admin.js`), читая их через `GET /api/subscribers`. Страница
без пароля и без ссылки в основном меню — подходит только для локальной разработки, не для
публикации в интернете как есть.

## Интерактивные элементы

1. **Квиз «Какая плата тебе подойдёт»** (`#quiz`) — логика полностью на клиенте (`frontend/js/quiz.js`),
   5 вопросов, очки суммируются по 7 платам, в конце показывается плата-победитель с обоснованием
   и ссылкой на её карточку в разделе «Виды плат».
2. **Форма подписки** (`#subscribe`) — клиентская валидация (`frontend/js/subscribeForm.js`) +
   серверная валидация (`backend/controllers/subscribe.controller.js`), реальный `POST` на
   `/api/subscribe`, статус отправки (`отправка... / успех / ошибка`) отображается прямо в форме.

## Чек-лист ручной проверки (без ошибок в консоли)

1. Запустить backend (`npm run dev`), открыть `http://localhost:3000` в Chrome/Firefox.
2. Открыть DevTools → вкладка **Console**: убедиться, что она пустая (нет ошибок/предупреждений)
   при загрузке страницы.
3. Прокрутить страницу сверху вниз — проверить, что блоки плавно появляются (scroll-reveal),
   консоль остаётся чистой.
4. Навести курсор на карточки плат — проверить hover-анимацию (подъём + тень), ошибок нет.
5. Уменьшить окно браузера до 320px (или включить мобильную эмуляцию в DevTools) — проверить,
   что раскрывается бургер-меню, вёрстка не ломается, таблица сравнения скроллится по горизонтали.
6. Пройти квиз до конца, нажать «Пройти ещё раз» — убедиться, что квиз сбрасывается корректно.
7. Отправить форму подписки:
   - с пустыми полями — должны появиться сообщения об ошибке под полями (клиентская валидация);
   - с некорректным e-mail — сообщение об ошибке;
   - с валидными данными — статус «Спасибо за подписку…», вкладка **Network** показывает
     `POST /api/subscribe` со статусом `201`;
   - повторная отправка того же e-mail — статус `409` и сообщение «Этот e-mail уже подписан».
8. Проверить `GET http://localhost:3000/api/subscribers` — новый подписчик появился в списке,
   а также в файле `backend/data/subscribers.json`.

## Стек и обоснование выбора

- **Frontend: чистые HTML/CSS/JS** — сайт учебный и не требует сборки; так проще гарантировать
  «без ошибок в консоли» и не тянуть лишние зависимости.
- **Backend: Node.js + Express** — минимальный, широко известный стек для простого REST API.
- **Хранилище: JSON-файл** — полноценная БД избыточна для формы из двух полей в учебном проекте.
- **Анимации: чистый CSS (transitions/keyframes) + нативный IntersectionObserver** — не требует
  подключения внешних библиотек (например, GSAP) и полностью соответствует требованию
  «без ошибок и предупреждений в консоли браузера».
